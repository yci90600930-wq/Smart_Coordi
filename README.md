# 스마트제조 코디네이터 자동 문서작성 시스템

CASE 4 (주)블루스카이로 시작하는 **로컬 단일 사용자 MVP**입니다. 기본 자동작성과 전사 후 요약·자동등록은 외부 AI 없이 규칙 기반으로 실행합니다. 마이크 실시간 전사는 브라우저 내장 음성인식 또는 선택적으로 OpenAI Realtime API를 사용합니다.

## 시작하기
Windows에서 `start.cmd`를 실행하고 [업무 화면](http://127.0.0.1:8765)을 엽니다. 이 PC의 번들 Python을 자동 사용하며, 다른 PC에서는 Python 3.12 이상을 설치한 후 실행합니다. 별도 패키지 설치는 필요 없습니다.

휴대폰에서도 사용할 때는 PC와 휴대폰을 같은 Wi-Fi에 연결하고 `start-mobile.cmd`를 실행합니다. 실행 창에 표시된 `Mobile URL` 전체를 휴대폰 Chrome 또는 Safari에서 엽니다. 같은 주소는 `data/mobile-access.txt`에도 저장됩니다. URL에는 임시 접속 토큰이 들어 있으며 서버를 다시 실행하면 바뀝니다. Windows 방화벽 안내가 나타나면 개인 네트워크만 허용합니다. PC의 `127.0.0.1` 접속은 토큰 없이 계속 사용할 수 있습니다.

### 외부에서도 사용하는 비공개 HTTPS 배포

기업 인터뷰와 사업비 자료를 공개 인터넷에 노출하지 않도록 Tailscale Serve 방식을 권장합니다.

1. PC와 휴대폰에 [Tailscale](https://tailscale.com/download)을 설치하고 같은 계정으로 로그인합니다.
2. PC에서 `start.cmd`를 실행해 앱을 시작합니다.
3. PC에서 `enable-secure-mobile.cmd`를 실행합니다. 최초 한 번은 Tailscale의 HTTPS 사용 승인 화면이 열릴 수 있습니다.
4. 출력된 `https://...ts.net` 주소를 휴대폰에서 엽니다. 이 주소는 같은 Tailscale 네트워크에 로그인한 기기에서만 접근할 수 있습니다.
5. 중지하려면 `disable-secure-mobile.cmd`를 실행합니다.

HTTPS 주소에서는 모바일 브라우저의 마이크 API를 사용할 수 있습니다. PC가 켜져 있고 앱과 Tailscale이 실행 중이어야 하며, SQLite와 HWPX 데이터는 PC의 `data/` 폴더에 계속 저장됩니다.

홈 화면에 설치하려면 iPhone Safari에서 공유 → **홈 화면에 추가** → **웹 앱으로 열기**를 사용합니다. Android Chrome에서는 메뉴 → **홈 화면에 추가** 또는 **앱 설치**를 선택합니다. PWA manifest와 정적 리소스용 service worker가 포함되어 있으며, 업무 데이터와 API 응답은 오프라인 캐시에 저장하지 않습니다.

### GitHub + Railway 클라우드 배포

GitHub에는 소스코드만 올리고 `data/`, `outputs/`, `reference/`, 로그, SQLite 및 `.env`는 `.gitignore`로 제외합니다. 실제 비밀번호와 `OPENAI_API_KEY`는 GitHub 파일에 넣지 않고 Railway Variables에만 등록합니다.

1. GitHub 저장소를 **Private**로 설정하고 이 폴더를 커밋·푸시합니다.
2. Railway에서 New Project → Deploy from GitHub repo로 저장소를 연결합니다. `Dockerfile`이 자동 감지됩니다.
3. 서비스 Variables에 `COORDINATOR_USERNAME`과 충분히 긴 `COORDINATOR_PASSWORD`를 설정합니다. 실시간 OpenAI 전사가 필요할 때만 `OPENAI_API_KEY`를 추가합니다.
4. 서비스에 Volume을 추가하고 mount path를 `/data`로 설정합니다. SQLite, 등록 HWPX, 백업 가능한 운영 데이터는 이 볼륨에 저장됩니다.
5. Settings → Networking에서 Domain을 생성합니다. Railway가 제공하는 `RAILWAY_PUBLIC_DOMAIN`을 서버가 자동 허용합니다.
6. 배포된 HTTPS 주소에 접속해 Basic 로그인, `/health`, 기업 등록, 재접속 후 데이터 유지 여부를 확인합니다.

Railway는 연결된 GitHub 브랜치의 변경을 자동 빌드·배포합니다. Volume이 없는 배포의 파일시스템은 재배포 때 초기화되므로 실제 운영 전에 `/data` 볼륨 연결이 필수입니다. 현재 로컬 DB는 GitHub에 올리지 않으며, 클라우드로 옮길 때는 별도 암호화 백업과 볼륨 반입 절차로 이전합니다.

직접 실행:
```powershell
python app.py
# 다른 포트 사용 시
python app.py --port 8766
```
실행 창을 닫거나 Ctrl+C를 누르면 서버가 종료됩니다. 저장 데이터는 재실행 후에도 유지됩니다. 인터넷 공개 서버로 실행하는 용도가 아닙니다.

## 사용 순서
0. **작업현황 → 실시간 대화 전사**에서 방문 차수를 선택하고 전사를 시작합니다. 전사 중에는 오른쪽 **현장 메모**에 관찰내용과 확인사항을 적습니다. **전사+메모 통합 요약·자동 등록**을 누르면 두 내용을 함께 분석한 요약과 문제·원인·개선과제·설비·데이터·KPI 후보가 새 원장 버전에 기록됩니다. 최근 기록을 펼치면 전사 원문, 메모, 요약을 모두 수정해 다시 반영할 수 있습니다.
1. **기업·근거**에서 기업정보와 자료 구분(교육/실제 현장)을 확인합니다. 각 값의 사실구분과 근거를 선택합니다. 출처는 자료명·페이지·면담일 등으로 구체화합니다.
2. **공정·진단 → 개선·설비 → 데이터·KPI → 사업비·공급기업**을 입력합니다. 항목 카드의 ID로 공정-문제-과제-설비-데이터-KPI를 연결합니다. 숫자를 알 수 없으면 빈칸으로 둡니다.
3. **방문·상태**에서 1·2·3차 당시 수행내용·상태·증빙을 기록합니다. 현재 구축상태는 별도 변경 버튼으로 근거·확인일·사유와 함께 다음 단계로 이동합니다.
4. **변경사항 저장**을 누릅니다. 변경사유와 함께 새 원장 버전이 저장됩니다.
5. **5종 문안 순차 생성**을 누릅니다. 1차→2차→3차→사업계획서→결과보고서가 같은 원장 버전에서 생성됩니다. 이전 문서는 그대로 보존됩니다. 문안 내려받기·복사·인쇄를 사용할 수 있습니다.
6. **일관성 검증**에서 숫자 근거, 사업비, 공정·설비 연결, 측정조건, 과거 문서 차이와 원자료 상충을 확인합니다. 검증은 저장된 원장 기준입니다.
7. 문서를 선택한 뒤 **HWPX 양식·출력**에서 해당 공식 양식을 선택합니다. 제공된 5종 원본에는 기본 매핑이 포함되어 있습니다. 입력 위치를 검토하고 HWPX 초안을 내려받습니다.
8. 최종 제출 전 한컴에서 **줄바꿈·표 높이·페이지 넘침·예시·사진·서명·날짜**를 확인합니다. XML 구조 검증과 화면 배치 검수는 별개입니다.

## CASE 4 데이터 해석
- 원본 실습 CASE: 현재 6개/일, 도입 후 기대 10개/일, H/W 4,200만 원, S/W 600만 원. 교육사례에 한정한 근거입니다.
- 기존 작성 사업계획서: ZX-5SA, 총사업비 6,000만 원(국비 3,600만/현금 1,200만/현물 1,200만). 현금 공급금액 합계 4,800만 원과 구분합니다. 당해연도 지원비율이나 적격성 확정값으로 사용하지 않습니다.
- 이전 대화 사용자 확인: 설치 완료 및 일 10개 생산. **사용자 진술**로 관리하며 측정기간·생산원장·확인일이 없으므로 객관적 성과달성을 자동 확정하지 않습니다.
- 기존 공정 8단계는 작성자료의 분석안입니다. 실제 현장공정 증빙과 구분합니다. CAM 신규도입을 추가하지 않습니다.
- 3차 설치 전/이후 설치 완료, 미래 제출완료일, 주소 표기 차이는 초기 상충항목으로 남깁니다. 매출의 ‘2억 미만’을 정확한 매출 2억으로 변환하지 않습니다.

## HWPX 출력 범위
공식 원본의 SHA-256와 지정 위치의 기존 텍스트를 확인한 후, 출력 복사본의 해당 텍스트만 바꿉니다. 원본 ZIP 구성, 표·이미지·서식은 보존하고 빈 run에는 텍스트 노드를 추가합니다. 별도 작성예시 페이지는 원본 그대로 남습니다. 각 실제 입력칸의 예시 문구는 매핑으로 대체합니다. Preview/PrvText와 Preview 이미지 등은 원본 상태여서 미리보기가 이전 내용일 수 있습니다.

현재 기본 매핑은 초안용입니다. 특정 표의 모든 상세항목이나 긴 문안의 시각적 수용성을 보장하지 않습니다. 미매핑 항목이 화면에 표시되며 최종 제출 상태를 자동 부여하지 않습니다. 새 공식 양식은 원본 등록 → 생성문서 선택 → 입력 위치 매핑 → 저장 순서로 추가합니다. 줄별 매핑은 상세 설정의 `line`(0부터)을 사용합니다. `expected`나 원본 해시가 다르면 출력을 거부합니다.

## 백업과 복원
왼쪽 아래 **자료 백업**은 현재 기업의 원장·버전이력·문서·감사기록을 JSON으로 내려받습니다. **복원**은 기존 기업을 덮어쓰지 않고 새 기업으로 원장·버전·문서를 복원합니다. 감사로그는 백업에 보존되지만 새 기업의 감사로그로 다시 실행하지 않습니다. HWPX 양식은 JSON 백업에 포함되지 않으므로 전체 이전 시 `data/` 폴더를 함께 복사하세요. 데이터베이스 파일을 직접 복사할 때는 서버를 종료합니다.

프로그램 전체를 백업하려면 `backup-all.cmd`를 실행합니다. SQLite 온라인 백업으로 실행 중인 데이터베이스의 일관된 사본을 만든 뒤 코드·화면·문서·HWPX 양식과 함께 `문서\SmartManufacturingBackups\coordinator-mvp-backup-YYYYMMDD-HHMMSS.zip`으로 저장합니다. 서버 로그, PID, 임시 모바일 접속 토큰과 Python 캐시는 제외합니다. 복구할 때는 앱을 종료하고 ZIP을 새 폴더에 푼 뒤 `start.cmd`를 실행합니다. 기존 운영 폴더에 바로 덮어쓰지 말고 새 폴더에서 데이터가 정상인지 먼저 확인합니다.

## 실시간 전사 범위
실시간 전사는 우선 OpenAI Realtime API의 `gpt-live-transcribe`를 사용하고, API 연결이 없을 때는 브라우저의 `SpeechRecognition`/`webkitSpeechRecognition`을 사용합니다. 둘 다 없으면 전사문을 직접 붙여넣거나 운영체제의 받아쓰기를 사용할 수 있습니다. 마이크 권한과 외부 음성 전송은 사용자가 **실시간 전사 시작**을 누를 때만 시작됩니다. 앱은 오디오 파일을 저장하지 않으며 확정된 전사 텍스트만 로컬 원장에 기록합니다.

Codex 내장 브라우저처럼 브라우저 음성인식이 없는 환경에서는 서버를 시작하기 전에 OpenAI API 키를 환경변수로 설정합니다. 키는 브라우저·SQLite·백업파일에 저장되지 않습니다.

```powershell
$env:OPENAI_API_KEY="여기에_API_키"
.\start.cmd
```

이미 실행 중이면 서버 창을 종료한 뒤 위 명령으로 다시 시작합니다. 화면 상단에 `OpenAI Realtime · 한국어`가 표시되면 연결 준비가 완료된 것입니다. API 사용량은 해당 OpenAI API 계정에 청구됩니다.

`음성인식 오류: network`는 Windows 마이크 권한 오류가 아니라 내장 브라우저의 음성인식 서비스 연결 실패입니다. 화면의 **Windows 음성입력**을 누르고 `Windows 키 + H`를 누르면 같은 전사 입력칸에 실시간으로 받아쓸 수 있습니다. 일반 Chrome 또는 Edge에서 `http://127.0.0.1:8765`를 열거나 위의 OpenAI Realtime 연결을 사용하는 방법도 지원합니다.

모바일에서는 **모바일 키보드 음성입력**을 누른 뒤 키보드의 마이크 아이콘을 누릅니다. iPhone은 키보드 받아쓰기, Android는 Gboard 또는 Samsung Keyboard의 음성입력을 사용합니다. 같은 Wi-Fi의 HTTP 접속에서는 모바일 브라우저 보안정책 때문에 웹앱의 **실시간 전사 시작** 마이크가 차단될 수 있지만, 키보드 받아쓰기는 전사 입력칸에 직접 입력되므로 사용할 수 있습니다. 웹앱 마이크 버튼까지 모바일에서 사용하려면 신뢰할 수 있는 HTTPS 주소로 배포해야 합니다.

요약과 항목 분류는 외부 AI 없이 전사 원문과 현장 메모를 합쳐 한국어 업무 키워드 규칙으로 수행합니다. 구두점 없는 긴 전사는 접속어·문장종결·업무 전환어를 기준으로 의미 구간을 나누고, 각 구간을 가장 관련 높은 항목 한 곳에 배정한 뒤 중복을 제거합니다. 최근 기록에서 원문·메모·요약을 직접 수정하거나 **자동 요약 다시 생성**으로 현재 규칙을 적용할 수 있습니다. 자동 등록 항목은 모두 `사용자 진술` 또는 `분석 및 판단`으로 표시됩니다. 발화 속 금액과 KPI 수치는 원문에만 보존하며 현재값·목표값·실적값에 넣지 않습니다. `검토→선정→발주→납품→설치→시범운영→운영→성과측정→성과달성` 상태도 전사만으로 변경하지 않습니다. 실제 증빙을 확인한 뒤 해당 화면에서 확정합니다.
